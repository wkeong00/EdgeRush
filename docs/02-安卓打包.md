## 通过 Unity 插件构建开发包

打开当前工程的锁定编辑器和 Pipeline。在仓库根目录运行：

```powershell
unity status --project-path (Get-Location).Path --format json
unity command build run --target Android --output-path Builds/Android/EdgeRush-0.1.0-dev.apk --options '["Development","DetailedBuildReport"]' --scenes '["Assets/Scenes/Main.unity"]' --confirm true --project-path (Get-Location).Path --caller plugin --skill unity-cli --format json
unity command build status --project-path (Get-Location).Path --caller plugin --skill unity-cli --format json
```

`queued`／`building` 不是完成；继续读 status，直到 `completed` 且 `Succeeded`。输出可含完整 BuildReport，应只展示摘要、保留本地日志。出包后重新检查文件和 SHA256，不复用旧报告。

当前未启用 Pipeline runtime 控制；首包仅含 Attributes，不含主控制运行时。依赖或启用符号变更后重新核对实际产物。

## 正式签名与身份

1. 首次上传前核对 TapTap 已有条目、厂商与包名可用性。工程和开发 APK 已采用 Gizmobyte／Edge Rush／`com.gizmobyte.edgerush`，后台占用尚未确认。
2. 用户尚不确定旧发布密钥。工作区与常用 Android 目录未找到，只能证明这些范围没有；若游戏曾以其他密钥发布，先找到并沿用，不能覆盖。
3. 确认需要新密钥后，按 [tools/README](../tools/README.md) 运行交互签名工具，在本机输入密码并独立备份。不要把私钥或密码放到聊天／GitHub。工具准备完成不等于密钥、备份或正式签名验收已完成。
4. 在 Unity **Player Settings → Publishing Settings** 配置 Custom Keystore、实际文件和 alias；密码只在本机处理。Apply Project Settings 会保留身份、版本与签名，不会替你填写。
5. 正式 APK 用 `apksigner verify --verbose --print-certs` 回读公开证书，记录 SHA256、版本和包哈希；Debug 证书不能代替发布证书。

## 正式 APK 还需满足

- 免费网站已公开，`BuildInfo.PrivacyPolicyUrl` 已指向当前内部测试版政策；接入真实 SDK 时更新政策并重新核对。
- 确定接受新竞价位／TapTap-only 的 SDK，完成隐私、真实测试广告与可靠奖励；现有广告 Release guard 仅识别旧 AdMob 分支，不能直接用于 Unity 新接法。
- 正式密钥、备份、版本及递增 versionCode 完成。按渠道／SDK确认 target API；开发包实际 target36 不代替最终要求核验。
- 生成非 Development 的正式签名 APK，再验证 Release guards、包身份、原生库和实际设备。用户当前未选择公开无广告替代首发。

独立 `ReleaseBuildValidation` 会阻断占位身份、政策 URL 和未配置签名；广告 guard 会阻断未完成的正式广告配置。不要绕过检查生成表面可提交的包。

## 模拟器与真机

用户目前没有 Android 真机。本机已有 BlueStacks，可尝试 ARM64 APK 的安装／启动和功能冒烟；此前仅启动过，未完成安装验收。Unity 官方不支持 Android 模拟器，不能替代触控、发热、性能、后台恢复或真实广告验收。[官方兼容性](https://docs.unity.com/en-us/engine/6000.6/manual/platform-specific/android/introducing/requirements-and-compatibility#emulator-compatibility)

借用真实 ARM64 Android 手机后，核验安装启动、教学、变道、暂停／返回、死亡结算、车库、签到任务、重启存档和长局。升级前核对旧包与签名，避免先卸载丢失旧档再误记升级通过；只有已授权且 USB 调试已准备的设备才使用 `adb install -r <apk>`。

黑屏、首次卡顿、崩溃和低帧率都记录实测持续时间与日志，不预先写成正常。体积、60 FPS、内存与温度以最终设备结果为准。
