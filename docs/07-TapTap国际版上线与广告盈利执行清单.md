## 1. 目标、范围与执行方式

首要目标是让真实玩家通过 TapTap 国际版下载 Edge Rush，游戏展示合规的真实广告，广告平台记录收入，最终达到结算条件并实际收款。先完成这条商业链路，再决定是否扩充内容或投入推广。

四个里程碑分开验收：

| 里程碑 | 完成的含义 | 不可替代的证据 |
| --- | --- | --- |
| M1 可发布 | 正式包、商店资料和设备测试通过，目标地区玩家可下载 | 商店链接、包版本、签名指纹、真机记录 |
| M2 有真实收入 | 所选广告平台账户／应用获准投放，真实玩家产生有效广告和收入记录 | 所选平台状态、曝光与收入报表；排除测试流量 |
| M3 已收款 | 必要付款验证完成，达到付款门槛，款项实际到账 | 平台付款状态与用户确认到账；不保存完整银行资料 |
| M4 验证盈利 | 在一个明确期间内，实际收入覆盖对应推广与运营成本 | 收入／成本记录、用户留存和广告数据 |

测试视频播放、Editor 编译通过、TapTap 审核通过、AdMob 报表中的预估收入，均不能互相替代上述证据。完成技术清单也不保证玩家数量或净利润。

## P12 · 银行收款方式、付款验证与首次到账

此阶段分“现在先做”和“达到条件后做”，不能机械地把所有付款待办放到注册当天。

| 事项 | 什么时候做 | 负责人 |
| --- | --- | --- |
| 初始付款资料：姓名／主体、地址、电话 | 注册后及账户审核阶段，见 A03 | 你 |
| 身份验证 | 后台提出要求时，在指定期限内处理 | 你 |
| 地址验证／PIN，或账户支持的替代流程 | 达到验证条件并收到后台提示后 | 你 |
| 银行等 payment method | 达到对应币种的选择门槛、后台开放入口后 | 你 |
| 税务表单、银行小额入账验证等 | 按账户所在地、所选方式和后台提示 | 你 |
| 首次付款与实际到账 | finalized 余额达到支付门槛且无暂扣后 | 你确认，我协助核对状态 |

- [ ] **P01｜你＋我**：记录账户实际报告币种和付款要求，不根据时区／估算收入猜测。初始付款资料已完成则引用 A03 证据，不重复填报。
- [ ] **P02｜你**：收到身份／地址／税务验证要求后按时完成；PIN 仅在官方页面输入，文档不保存。未收到要求时标记“待触发”，不误记验证失败。
- [ ] **P03｜你**：付款方式入口开放后，在 **Payments → Payments info → Manage payment methods／Add payment method** 等实际菜单中添加支持的银行方式并设为主要方式；没有入口先检查门槛和暂扣提示。
- [ ] **P04｜你**：如所选方式要求银行小额入账验证，按到账记录在官方后台完成；需要邮寄验证则确认真实地址能收信。
- [ ] **P05｜共同**：检查 Payment holds、身份／地址／税务待办和付款门槛；区分报表预估收入、已结算余额、付款已发出与银行已到账。

- [ ] **P07｜我＋你**：若付款失败或退回，记录平台原因，先修资料／验证或联系官方支持，不反复创建广告账户。

| 报告币种 | 选择付款方式门槛 | 支付门槛 |
| --- | ---: | ---: |

| SGD | S$15 | S$150 |

| EUR | €10 | €70 |
