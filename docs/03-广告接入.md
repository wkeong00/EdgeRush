# 03 · 广告接入（激励视频）

## 先说清楚一件事

你给的 `tapsdk integration.txt` 和 `developer center configuration.docx` 是 **TapSDK / TapTap 开发者服务** 的文档，它提供的是 **TapTap 登录、内购、TapDB 分析**，**不提供广告变现**。

- 想在 TapTap 国际版靠广告赚钱，需要接入 **第三方广告平台**：**Google AdMob**（推荐）或 **Unity LevelPlay**。
- **TapSDK 不是上架必需**，v1 完全可以不接。只有你想做「TapTap 账号登录 / 成就 / TapTap 好友榜」时才需要，而且那时才需要在开发者后台登记签名 MD5。

所以本工程的广告层是 AdMob（预留了替换接口）。

## 现在工程里的状态

- `Assets/Scripts/Systems/Ads.cs`
  - `IAdProvider`：广告接口。
  - `AdManager`：4 个广告位的加载、展示、频次、埋点、音频静音。
  - `MockAdProvider`：编辑器 / 未接 SDK 时使用的 **测试广告**（全屏，3 秒倒计时，可点 SKIP 模拟「没看完」）。
  - `AdMobProvider`：真实 AdMob 适配层，用 `#if EDGERUSH_ADMOB` 包裹，**默认不参与编译**。
- 4 个广告位（`AdPlacement`）：复活、结算双倍金币、每日奖励、皮肤解锁。**没有插屏、没有强制广告**，符合文档 7.1。

## 接入 AdMob 的完整步骤

### 1. 注册并建应用

1. https://admob.google.com → 注册（需要 Google 账号 + 收款信息，中国大陆个人可用，注意税务表单）。
2. **Apps → Add app** → Android → 填游戏名（可先不发布到商店，AdMob 允许"未上架"状态）。
3. 记下 **App ID**，形如 `ca-app-pub-1234567890123456~1234567890`。

### 2. 建 4 个激励视频广告单元

**Apps → 你的应用 → Ad units → Add ad unit → Rewarded**

| 广告位 | 建议命名 | 用途 |
| --- | --- | --- |
| Revive | `edge_rush_revive` | 失败后复活（收入主力） |
| DoubleCoins | `edge_rush_double_coins` | 结算金币翻倍 |
| DailyBonus | `edge_rush_daily` | 每日额外金币 |
| SkinUnlock | `edge_rush_skin` | 集齐 5 次解锁皮肤 |

每个单元会给你一个 ID，形如 `ca-app-pub-1234567890123456/9876543210`。

> 刚建的广告单元通常需要 **几小时到 24 小时** 才开始填充。期间用 Google 官方测试 ID（下面有）。

### 3. 安装 Google Mobile Ads Unity 插件

1. 下载：https://developers.google.com/admob/unity/quick-start （`.unitypackage`，v9.x）。
2. Unity 里 **Assets → Import Package → Custom Package** 选它，全部勾选导入。
3. 导入后会弹 **Google Mobile Ads Settings** 窗口，把 **App ID** 填进去（这一步会写入 `Assets/GoogleMobileAds/Resources/GoogleMobileAdsSettings.asset`，不要漏，否则启动崩）。
4. 如果没弹窗：`Assets → Google Mobile Ads → Settings`。

### 4. 打开本工程的适配层

1. `Edit → Project Settings → Player → Other Settings → Scripting Define Symbols`
   加一条：`EDGERUSH_ADMOB`（多个 define 用 `;` 分隔）。
2. 打开 `Assets/Scripts/Systems/Ads.cs`，找到 `AdMobProvider.UnitIds`，把 4 个测试 ID 换成你自己的：

```csharp
static readonly Dictionary<AdPlacement, string> UnitIds = new Dictionary<AdPlacement, string>
{
    { AdPlacement.Revive,      "ca-app-pub-你的ID/你的单元" },
    { AdPlacement.DoubleCoins, "ca-app-pub-你的ID/你的单元" },
    { AdPlacement.DailyBonus,  "ca-app-pub-你的ID/你的单元" },
    { AdPlacement.SkinUnlock,  "ca-app-pub-你的ID/你的单元" },
};
```

3. 改完后 `AdManager.CreateProvider()` 会自动选 AdMob；否则退回 Mock。

> 现在文件里预填的是 Google 官方 **测试激励视频 ID**（`ca-app-pub-3940256099942544/5224354917`），可以先用它跑通全流程，看到广告、拿到奖励，再换正式 ID。

### 5. 联调检查清单

- [ ] 真机上点「看广告复活」能拉起全屏视频
- [ ] 看完 → 复活成功、连击保留、2 秒无敌闪烁
- [ ] 中途关闭 → 不复活，直接进结算（不能给奖励）
- [ ] 结算页「双倍金币」看完 → 金币 ×2，且该局不能看第二次
- [ ] 每日奖励看广告 → +30 金币，每天最多 3 次
- [ ] 断网 → 按钮消失或点了给 Toast，不卡死、不崩
- [ ] 广告播放时游戏音乐静音，结束恢复

### 6. 上架前的合规（**必做**）

1. **App ID 必须是正式 ID**，测试 ID 上架会被拒/不产生收入。
2. **欧盟用户同意（GDPR / UMP）**：AdMob 提供 User Messaging Platform (UMP) SDK。Unity 插件里已有 `GoogleMobileAds.Ump` 命名空间，需要在启动时请求 consent：
   - 官方说明：https://developers.google.com/admob/unity/privacy
   - 简要流程：`ConsentInformation.Update()` → 需要时 `ConsentForm.LoadAndShowConsentFormIfRequired()` → 用户同意后再 `MobileAds.Initialize`。
   - **本工程尚未内置 UMP 同意弹窗**（见 `05-已完成与待办.md`），如果你的目标市场包含欧盟/英国，这一项必须在提交前补上。东南亚市场可以先不做，但建议做。
3. **隐私政策**：AdMob 会收集广告 ID 等设备标识，TapTap 开发者协议也要求你向用户提供隐私说明。写一页静态网页，把链接填到 `Assets/Scripts/Core/BuildInfo.cs` 的 `PrivacyPolicyUrl`，并放进商店描述。
4. **不要自己点自己的广告**（会被封号）。测试请用测试 ID 或把设备加进 AdMob 的测试设备列表。

### 7. 收益的现实预期

超休闲 + 激励视频，eCPM 在东南亚大约 **$3–$12**（激励视频高于插屏）。按文档目标「每 DAU 每天 4 次展示」：

```
1000 DAU × 4 次 × $6 eCPM / 1000 ≈ $24 / 天
```

也就是说 **流量才是瓶颈**，广告接入只是把流量变成钱。文档 14 节说的短视频推广、商店素材质量，比再多写一个广告位重要得多。

## 换平台（Unity LevelPlay）

如果你想用 ironSource/LevelPlay 做聚合：实现一个新的 `IAdProvider`（4 个方法），在 `AdManager.CreateProvider()` 里返回它即可，其余代码不用动。Unity 6 里 LevelPlay 有官方包 `com.unity.services.levelplay`（Package Manager 可装）。
