# 03 · 激励广告接入与验收

> 更新：2026-10-28。工作基线为《优化方案 v2.0》。本页区分本轮代码能力与尚未验证的真实商业接入；未查看广告账户、收款后台或真实填充。

## 渠道先决条件

TapTap 发布和第三方广告变现需要分别确认。v2 查核的 Google 支持商店列表没有 TapTap；不能把“仅 TapTap 分发＋AdMob”视为已经成立的完整收入路线。准备采用 AdMob 时，先确认可实际使用的支持商店、应用关联、账户与应用审核；若只在 TapTap 分发，先向候选广告网络确认发行方式、主体、国家与收款条件。采用聚合也需要确认各需求方条件。

来源：[Google 商店关联说明](https://support.google.com/admob/answer/10037806?hl=en)、[应用 readiness](https://support.google.com/admob/answer/10564477?hl=en)。实际接入前复核当前规则和账户后台。测试视频成功不代表正式投放已获批准。

TapSDK／TapTap 开发者服务不等同于广告 Provider。当前工程未接 TapSDK；是否接登录等服务按实际产品需求和所选服务文档决定。

## 目前工程状态

`Assets/Scripts/Systems/Ads.cs` 已提供：

- `IAdProvider`：异步初始化、加载、清理、展示、销毁接口。
- `AdManager`：单广告位单飞加载，初始化／加载超时边界，最多四次尝试及退避，旧加载回调隔离，Unity 主线程投递，音频恢复。
- `AdConfiguration`：广告开关、每日／皮肤入口开关、统一 60 秒间隔、前三个正式完成局的资格规则。`UnitIds` 当前留空。
- `MockAdProvider`：仅 Editor／Development 编译；支持成功、跳过、关闭、失败和可配置延迟。SKIP 与 CLOSE 都走已保存的结束回调。
- `AdMobProvider`：条件编译的适配代码；尚未安装、锁定或验证真实 SDK，未接 UMP。
- `Assets/Editor/AdBuildValidation.cs`：正式构建检查。广告启用时，缺真实 Provider 定义、缺有效正式单元 ID、使用 Google 测试 publisher ID 均阻断 Release。运行时缺配置会禁用广告，Release 不回退 Mock。要发布无广告版本需明确将 `AdConfiguration.AdsEnabled` 关闭。

四个入口均为玩家主动选择激励视频；没有新增自动插屏。可用性在展示前再次检查，页面保留稳定的禁用状态与简短原因。广告资格在正式开局快照，避免第三局结算刚增加完成局数就提前露出广告。

| 广告位 | 本轮初始规则 |
| --- | --- |
| Revive | 每局一次；新玩家前三个正式完成局不露出；拒绝后正常结算 |
| DoubleCoins | 基础本局金币先到账；广告只补一次相同基数；前三局不露出 |
| DailyBonus | 每日最多三次；当前奖励 30 金币；可配置关闭 |
| SkinUnlock | Chrome Ghost 累计五次进度；可配置关闭 |

全广告位共享 60 秒间隔；一次复活后较短时间进入结算，翻倍入口可能处于冷却。广告不可用不影响免费游玩。

## 确定 Provider 后的接入步骤（D 批次）

1. 确认发行渠道、广告网络、账户主体、收款地区和包名；按最终后台要求创建应用及所需单元，不预设任何地区或个人账户必然可用。
2. 按[Google Unity 接入指南](https://developers.google.com/admob/unity/quick-start)选择并锁定实际 SDK 版本，记录依赖和 Android 要求。旧文档的 v9.x 不作为本工程固定版本。
3. 在插件当前设置入口填写 App ID。App ID（含 `~`）与单元 ID（含 `/`）分开配置；核对插件生成的 Android 配置。
4. 对照[激励广告官方接口](https://developers.google.com/admob/unity/rewarded)编译核验适配层。完成隐私流程后，才按请求资格初始化／加载。加 `EDGERUSH_ADMOB` 前须确保 SDK 已安装且所有分支能编译。
5. 将所需单元写入 `AdConfiguration.UnitIds`。开发时使用官方测试配置或测试设备；正式单元必须配合测试设备验证，不自行点击正式广告。正式构建不能携带 Google 测试 publisher ID。
6. 用真实 Android 设备验证下面的完整矩阵，再核对应用关联、readiness、真实曝光与收入后台。SDK 接入完成本身不代表有填充或收入。

如果改用 LevelPlay 或其他网络，应实现同一异步 Provider 契约，并增加匹配的 Release 配置校验；不能只替换类名后认定可上线。

## 奖励回调契约与当前限制

```csharp
Ads.Show(placement,
    onClosed: earned => { /* 恢复 UI／玩法；不在这里发金币 */ },
    onReward: showId => { /* 用 showId／runId 幂等提交并立即保存奖励 */ });
```

请求、打开、SDK 曝光、奖励、关闭、失败分别记录；`ad_paid` 只取 SDK 收入事件，不用奖励次数推算收入。本地事件尚未上传到运营分析服务。

奖励回调是持久化边界；关闭只负责恢复。已获得的奖励不会因为之后关闭失败而撤回。重复奖励和关闭不会重复执行；销毁、过期加载回调不应回写当前状态。缺关闭时不会简单计时后自动继续跑局；返回 Unity 画面后可使用恢复操作，仍需真机验证。

**D 批次必须补齐合法乱序回调。** 当前守卫会忽略已关闭展示的后续奖励，避免陈旧回调改写状态；真实聚合源可能先关闭、后发奖励。接最终 Provider 时，需用 `showId` 保留可幂等提交的奖励凭据，并明确复活待决或补偿策略。当前 Mock 固定先奖励、后关闭，不能证明该场景已通过。[Google Android 奖励事件顺序说明](https://developers.google.com/admob/android/rewarded)

## 隐私与数据

按发行地区、实际受众、最终 SDK 和平台规则配置隐私流程。不能根据“面向东南亚”省略评估，也不能把拒绝个性化直接当作所有广告都不可请求。

采用 AdMob 时，每次启动更新 UMP 状态，按 `CanRequestAds()` 决定是否请求，避免重复初始化／加载，并提供要求的隐私选项入口。[Google UMP 指南](https://developers.google.com/admob/unity/privacy?hl=en)

`BuildInfo.PrivacyPolicyUrl` 仍是占位地址。公开政策需准确列明最终 SDK、数据用途、联系方式与用户选择；年龄／儿童定向按实际受众和平台规则配置。TapTap 财务服务权限与广告平台收款资格分别确认。

## 联调与发布验收

- [ ] 固定 SDK 版本，真实 Provider 分支与 Android 依赖编译通过。
- [ ] 初始化失败、无填充、断网、加载超时与重试上限表现明确，无重复全量加载。
- [ ] 成功、跳过、关闭、展示失败、重复回调、先关闭后奖励、缺关闭均验证；已到账奖励不丢失、不重复。
- [ ] 广告打开／曝光／奖励分别有 SDK 证据；收入按支持的 paid 回调或后台按日对账。
- [ ] 切后台／回前台、音频恢复、页面销毁后回调、立即退出后重启均验证。
- [ ] 复活、翻倍、每日奖励、皮肤进度的限额和幂等行为通过；前三局和 60 秒共享间隔通过。
- [ ] UMP 与隐私选项入口、测试设备配置、正式包配置和商店／账户 readiness 一致。

收入仅在有实际数据后计算：日收入约等于 DAU × 每 DAU 实际曝光 × 实际 eCPM ÷ 1000。这里不提供地区 eCPM、填充等待时间或收益承诺。
