# 04 · TapTap 国际版发布准备

> 更新：2026-10-28。依据《优化方案 v2.0》纠正旧文档；本轮未登录开发者后台、提交商店审核或验证第三方广告收入。下列步骤是准备与验收清单，不是平台审核保证。

## 发行范围与账号

本项目继续以 TapTap 国际版、Android、免费游玩、玩家主动选择激励广告为目标。国际开发者中心使用 [developer.taptap.io](https://developer.taptap.io/)，创建和注册流程参照[国际版游戏创建](https://developer.taptap.io/docs/store/store-creategame/)与[开发者注册说明](https://developer.taptap.io/docs/store/)。实际注册条件、实名或企业资料、服务权限、文件格式和审核进度，以当前官方规则和用户后台为准。

TapTap 开发者财务权限与第三方广告平台结算属于两条链路。不能用“需要 TapTap Verified 才能赚广告钱”代替广告账户、主体、收款地区与渠道资格核验。

如果改为中国大陆发行，需要另行评估发行资质、广告网络、隐私与平台服务；不直接套用国际版结论。[国内规则参考](https://developer.taptap.cn/docs/store/standardies-operation/)

## 创建游戏与包配置

1. 确认正式英文名、支持联系方式与主体，按后台流程创建游戏。
2. 确定稳定包名，并同步 `Assets/Scripts/Core/BuildInfo.cs`、Player Settings 与开发者后台。当前 `com.yourstudio.edgerush` 仍是占位值。
3. 使用锁定的 Unity `6000.6.7f1` 编译。项目现有 Android 基线为 IL2CPP／ARM64；目标 API、最低 API 与依赖按最终商店和 SDK 要求核对，不沿用旧文档未经核实的未来日期／API 断言。
4. 准备签名、密钥备份、版本号与递增的 versionCode；确认实际 APK 使用正式配置。调用自动项目配置后重新核对包名、签名和版本，避免示例默认值覆盖发布配置。
5. 按后台当前要求提交 APK 与资料。文件类型、包大小限制、审核时间和定时发布要求均在提交前复核，不把旧文档数值当作固定规则。

打包操作可参照 `02-安卓打包.md`，但其中平台要求、版本、签名和包名需以本页与最终后台复核结果为准。

## 商店素材与公开资料

| 资料 | 准备方式与验收 |
| --- | --- |
| 图标／封面 | 使用清晰可辨的车辆与游戏名称；尺寸、格式、裁切安全区按当前后台确认 |
| 游戏截图 | 来自实际 Unity／Android 运行，包含玩法、擦边、结算、车库等已实现画面；提交前核对数量与尺寸 |
| 宣传视频 | 录制实际玩法，突出单指变道与擦边连击；时长、格式、封面按当前后台确认 |
| 英文简介／更新说明 | 描述真实可用功能，不写已上线盈利、保证收入或尚未完成的内容 |
| 隐私政策 | 可公开访问，准确列明最终 SDK、数据用途、联系方式与用户选择；替换 `BuildInfo.PrivacyPolicyUrl` 占位地址 |
| 年龄分级 | 如实完成实际问卷，并核对广告受众配置；不能仅因为含广告写成固定 12+／Teen |
| 支持联系渠道 | 提供可使用的邮箱或支持入口，并与政策及商店资料一致 |

现有 `art-preview-*.png` 是离线美术示意，不能当作已实现的游戏运行截图。旧文档中的图标、截图、封面、视频尺寸可作历史草稿参考，提交时必须重查当前后台。

## 广告路线是单独的发布门槛

v2 查核的 Google 支持关联商店列表没有 TapTap，不能据 TapTap 上架推定 AdMob 已可完整变现。若选 AdMob，需要确认可实际使用的支持商店和应用关联、账户与应用审核；若坚持仅 TapTap 分发，先向候选网络确认该方式可用。[Google 商店关联](https://support.google.com/admob/answer/10037806?hl=en)、[应用 readiness](https://support.google.com/admob/answer/10564477?hl=en)

本轮尚未选定并验证最终 Provider，没有真实 SDK、账户填充或到账证据。目前 Release 构建会阻断“广告启用但没有正式 Provider／有效单元配置”的情况；Mock 仅 Editor／Development 使用。真实 SDK、隐私、合法乱序奖励回调和广告往返验证按 `03-广告接入.md` 完成。

当前产品只提供主动选择的激励入口，但最终广告素材、可关闭性、SDK 行为、隐私和商店政策仍需实际验收。不能仅凭入口设计声明“完全合规”。

## TapSDK、签名与平台服务

当前工程未接 TapSDK。登录、好友等平台服务按实际需要接入，参考当时有效的官方说明；已有 `tapsdk integration.txt` 与配置文档可作背景资料，不能作为当前 SDK 版本与权限的唯一依据。

游戏包签名与某项平台服务要求登记的签名指纹分别核对。只有确定使用的服务后，才按该服务说明配置 Client ID、地区、签名指纹与混淆规则；不把旧文档的统一 MD5 步骤当作所有发布场景的要求。

## Release 候选包验收

- [ ] 正式包名、签名、版本号、versionCode 与后台一致，密钥已备份。
- [ ] Unity 编译、Editor 流程与实际截图完成；所有 P0 问题清零。
- [ ] 低档和中档 Android 设备验证触摸、安全区、系统返回、切后台、断网与广告往返。
- [ ] 干净安装和旧版本升级两条路径通过；金币、皮肤、广告进度、签到和任务无丢失或重复发奖。
- [ ] 16:9、18:9、19.5:9、20:9 及刘海／手势区屏幕检查无遮挡，按钮可实际操作。
- [ ] 真实 Provider、隐私流程、测试设备、商店支持与账户 readiness 已确认；正式包禁止 Mock 和测试 publisher ID。
- [ ] 实测长局性能、内存、温度与冷启动；记录设备型号、分辨率、版本与结果。
- [ ] 商店素材来自实际运行且与发布功能一致；公开政策和支持链接可用。
- [ ] 商店当前文件、素材、API、年龄问卷与审核要求已按实际后台复核。

小流量测试按 v2 先检查教学、再次开局、留存和经济，再判断是否扩大分发。提交审核、通过审核、可获客、可展示测试广告、真实变现应分别记录。
